# 模拟盘实验结果与验收边界

## 范围与版本

运行日期为 2026-09-30，版本 `bffe06100b06d8014ed5a2d3f4f7f708d97419a0`。工具链为 Ubuntu 18.04 容器内 GCC 8.4 / CMake 3.10；升级后的宿主运行该容器，不等于已用宿主原生新工具链构建。

所有价格与盘口为人工数据，发送目标间隔 100ms。原生 Tick 结构 512 字节，UDP 包 516 字节。实验仅通过中台输入；本地撮合来自原 `TraderMocker`，没有柜台接入。

总输入 520 条，中台接受 491 条；差额 29 条来自恢复第二阶段累计量倒退。恢复链共存储 61 条，即 30+1+30。存储检查按本版原生块结构读取，并逐条匹配输入时间，不只依赖日志行数。

三手开、平两个订单分别对应 `1+1+1` 手成交。恢复链累计仅一笔开仓与一笔平仓，没有因恢复重复开仓。

第二阶段恢复持仓成功，行情却被累计量校验拒绝。最后一条等于缓存累计量的输入被接受，又落在首 Tick 初始化分支，所以策略仍为零回调。第三阶段续接累计量后正常平仓。

## 理论与通道成交

| 基线 2 | 4001 × 1 | 4001 × 1 | 0 |

| 三手分笔 | 4001、4002、4003，各 1 | 4000、4001、4002，各 1 | -30 |

策略理论一手成交为 4003 开、4001 平，毛盈亏 -20；三手为 -60。它与通道成交属于不同记账路径。

`newpx` 对照没有固定相同的订单到达和撮合报价时刻，因此不能将盈亏差异全部归因于取最新价或对手价。
